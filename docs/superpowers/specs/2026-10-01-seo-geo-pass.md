# SEO and GEO pass — spec (2026-10-01)

Goal: make every Knackdesk page strong for search engines and AI answer engines, generated by the build so future tools inherit it. No new dependencies, no runtime JS beyond what exists, static output only. All behaviour below is covered by Vitest tests on the build/layout functions.

## 1. Structured data (JSON-LD), emitted by `shared/layout.js` / `scripts/build-site.js`
- Every page: `Organization` (name Knackdesk, url https://knackdesk.com, logo https://knackdesk.com/icon.svg, contactPoint email hello@knackdesk.com) and `WebSite` (name, url) on the home page only; `BreadcrumbList` (Home → page) on every non-home page.
- Tool pages: `WebApplication` { name, url, description, applicationCategory "BusinessApplication", operatingSystem "Any", offers { price 0, priceCurrency USD }, isAccessibleForFree true, provider Organization }.
- Tool pages: `FAQPage` built automatically from the page's `<h2>Frequently asked questions</h2>` section: each `<h3>` is a Question, the following `<p>` (text, tags stripped) is the acceptedAnswer. Skip if the section is absent.
- Digital products (kit cards on home): `Product` with offers (price from price_cents, USD, url = polar_url, availability InStock), seller Organization.
- One `<script type="application/ld+json">` per page containing a `@graph` array. JSON must be valid; `</script>` inside strings escaped as `<\/script>`.

## 2. Meta tags (layout)
- Open Graph: og:type (website / article for tools), og:title, og:description, og:url, og:site_name Knackdesk, og:image https://knackdesk.com/og.png (1200×630). Twitter: card summary_large_image, title, description, image.
- `<link rel="icon" href="/icon.svg">` and `<link rel="apple-touch-icon" href="/apple-touch-icon.png">`.
- `<meta name="robots" content="index,follow,max-image-preview:large">`.
- Keep existing canonical, description, viewport.

## 3. Assets (static, in `site/public/`)
- `icon.svg`: simple mark, letter K in the accent colour on a rounded square; `apple-touch-icon.png` 180×180 and `og.png` 1200×630 generated from the SVG by a Python script using Pillow in the project .venv (install Pillow into .venv; the PNGs are committed, generation script kept in `scripts/make-icons.py`). og.png: dark background, "Knackdesk" wordmark and the line "Small, useful tools and kits for freelancers".

## 4. E-E-A-T and page content
- Each tool page gets, right under the h1 intro, a `<p class="byline">By the Knackdesk team · Last reviewed <date></p>` where the date comes from the PLAN.md front-matter field `reviewed:` (YYYY-MM-DD); add `reviewed: 2026-10-01` to all 20 tool PLANs. Build inserts it; test it.
- Each tool page gets a definition block immediately after the intro paragraph: `<p class="definition"><strong>In one sentence:</strong> …</p>` and a `<p class="formula"><strong>Formula:</strong> …</p>`. These are written per page (hand-written content, 20 pages) — concise, factual, matching calc.js.
- About page rewritten (250+ words): who makes it (a small studio, run by a software engineer, Croatia-based, since 2026), what the tools are, how they are built and checked (unit tests; every formula verified), how to report an error, the not-advice position, and that the site is supported by kit sales and ads.
- Home page: intro paragraph, then tools grouped by category with a one-line description per category: Invoicing & payment (invoice-due-date, late-fee-calculator, early-payment-discount, deposit-split-calculator, vat-calculator), Rates & pricing (hourly-rate-calculator, day-rate-to-salary, markup-margin-calculator, price-increase-calculator, discount-calculator, effective-hourly-rate, retainer-calculator, commission-calculator), Planning & cash (break-even-calculator, revenue-goal-calculator, cash-runway-calculator, saas-cost-calculator), Time & pay (hours-to-decimal, working-days-calculator, overtime-calculator). Categories come from a `category:` field added to each PLAN front-matter (values: invoicing, pricing, planning, time); build groups cards by it; kits in their own "Kits" section. Test it.
- Titles: keep `<title>` as is (name · Knackdesk) but add `headline:` field support in PLAN front-matter that, when present, overrides the `<!-- title -->` for `<title>` and og:title only (not h1). Set headlines for the 20 tools with the long-tail angle, e.g. "Invoice Due Date Calculator (Net 30, Net 60, Business Days)", "Late Payment Fee Calculator: Flat Fee or Monthly Interest", under 60 characters each.

## 5. GEO files
- `llms.txt` at site root: H1 "Knackdesk", one-paragraph summary, then "## Tools" with one line per tool `- [Name](url): tagline`, "## Kits" with the two products and prices, "## About" link, generated by the build from the catalog. `llms-full.txt`: same plus each tool's definition and formula lines. Test both.
- `robots.txt`: keep allow-all; add explicit `User-agent: GPTBot`, `ClaudeBot`, `PerplexityBot`, `Google-Extended` blocks with `Allow: /`, and a `# llms.txt: https://knackdesk.com/llms.txt` comment.

## 6. Verification
- Vitest tests for: JSON-LD presence and validity (JSON.parse) on home, tool and kit cases; FAQPage extraction; breadcrumbs; og tags; byline date; category grouping; llms.txt content; headline override.
- After deploy, fetch three live pages and validate the JSON-LD parses and includes WebApplication + FAQPage; validate one URL with Google's Rich Results Test manually (owner or via browser).

## Out of scope
Backlinks, directory submissions, AdSense tags (already conditional), content rewrites beyond the definition/formula blocks and About.
